# 开发者模式（片 A/B）：内容外置 + 手机现场采点

## Context

目前全部游戏内容硬编码在 Kotlin 单例里，约 52 处构造点分布在 6 个文件（[FakePlaceRepository.kt](file:///e:/DreamingPath/RainingTrace/app/src/main/java/com/rainingtrace/data/repository/FakePlaceRepository.kt) 9 地点 + 15 别名、[FakeNpcRepository.kt](file:///e:/DreamingPath/RainingTrace/app/src/main/java/com/rainingtrace/data/repository/FakeNpcRepository.kt) 5 人、[FakeNpcProactiveRuleCatalog.kt](file:///e:/DreamingPath/RainingTrace/app/src/main/java/com/rainingtrace/data/repository/FakeNpcProactiveRuleCatalog.kt) 10 条、[InventoryState.kt](file:///e:/DreamingPath/RainingTrace/app/src/main/java/com/rainingtrace/domain/inventory/InventoryState.kt#L118-L308) 18 资源、[ResourceYieldRule.kt](file:///e:/DreamingPath/RainingTrace/app/src/main/java/com/rainingtrace/domain/world/ResourceYieldRule.kt#L266-L288) 21 规则、[NpcLineCatalog.kt](file:///e:/DreamingPath/RainingTrace/app/src/main/java/com/rainingtrace/domain/npc/NpcLineCatalog.kt) 约 60 组台词 + [RuleBasedNpcMessageParser.kt](file:///e:/DreamingPath/RainingTrace/app/src/main/java/com/rainingtrace/domain/npc/RuleBasedNpcMessageParser.kt#L9-L46) 关键词表）。

加一个地点 = 改代码 + 重编译 + 重装包。用户作为唯一设计者兼测试者，**出内容的速度就是产品的速度**，所以先做开发者模式。目标：改内容不重编译；站在门口就能记一个新地点。

代码本来就为这天留了口子（`ResourceYieldRule` / `WorldCondition` 的 KDoc 都写着"将来搬进开发者编辑器无需改核心代码"，且所有 InMemory 实现都已经是 `(list) -> 接口` 的形态），`kotlinx.serialization.json` 已在依赖里但零使用。

### 已确认的三个决策

1. **只加 `Not`**，不加 `AnyOf`。必须同时修 `specificity`（否则否定条件会被当成"更具体"）。
2. 覆盖层用**完整条目替换**（改写内置内容时从内置 JSON 拷一份改），不做补丁式。
3. 最后**拆掉 Kotlin 硬编码常量**，JSON 成为唯一真相。

## 一、JSON 布局与 schema

一类文件一份（不打包成单一 pack）：改地点不会碰到台词，单个文件语法错误不会毁掉整个世界。

```
app/src/main/assets/content/{places,resources,yield_rules,npcs,
  npc_proactive_rules,npc_lines,place_aliases,npc_keywords}.json   // 内置默认
<filesDir>/content/<同名 8 个>.json                                 // 用户覆盖层，全部可选
```

**实体型文件**（places / resources / yield_rules / npcs / npc_proactive_rules）统一根结构：

```json
{ "schemaVersion": 1, "removedIds": ["place.bit.orchard"], "entries": [ ... ] }
```

**映射型文件**（其余 3 个）各自根结构：

```json
// npc_lines.json      —— 每个 key 整体替换
{ "schemaVersion": 1, "removedKeys": [], "lines": { "greet.stranger": ["你好。", "…"] } }
// place_aliases.json
{ "schemaVersion": 1, "removedAliases": [], "aliases": { "北湖": "place.bit.north_lake" } }
// npc_keywords.json   —— 整块替换（不分条目）
{ "schemaVersion": 1, "topics": {"BOOKS": ["书", "看书"]}, "times": [{"text": "明天下午", "hint": "TOMORROW_AFTERNOON"}],
  "meet": ["等我"], "scheduleQuestions": ["在哪"], "questionMarkers": ["？"] }
```

各实体条目示例：

```json
// places.json
{ "id":"place.bit.north_lake", "name":"北湖", "type":"LAKE",
  "lat":39.7326, "lng":116.1712, "actions":["OBSERVE","COLLECT"], "description":"…" }

// resources.json
{ "id":"res.rain_moss", "name":"雨生苔痕", "category":"NATURE", "rarity":"COMMON",
  "tags":["moss","rain","garden"], "description":"…" }

// yield_rules.json
{ "id":"rule.observe.rainy_lake", "resourceId":"res.lake_memory_fragment", "action":"OBSERVE",
  "placeType":"LAKE", "amount":1, "cooldownMs":1800000, "conditions":[{"type":"weatherIn","kinds":["RAINY"]}] }

// npcs.json
{ "id":"npc.bit.lin", "name":"林", "oneLiner":"…", "role":"大二学生",
  "traits":["TACITURN","PUNCTUAL"], "topics":["BOOKS","SELF"], "favoriteTopic":"BOOKS", "backstory":["…"],
  "schedule":[{"startMinute":420, "placeId":"place.bit.dorm_3", "travelMinutes":0, "activity":"刚起床，收拾书包"}] }

// npc_proactive_rules.json
{ "id":"rule.lin.rain_library", "npcId":"npc.bit.lin", "cooldownMs":43200000, "priority":0,
  "text":"下雨了，{place}这边人少，挺安静的。",
  "condition":{"type":"all","conditions":[
    {"type":"weatherBecame","kinds":["RAINY"]},
    {"type":"world","condition":{"type":"timeOfDayIn","times":["DAY"]}}]} }
```

### `WorldCondition` 判别式联合（`type` 与 sealed 子类一一对应）

```json
{"type":"weatherIn","kinds":["LIGHT_RAIN","HEAVY_RAIN"]}
{"type":"timeOfDayIn","times":["NIGHT","DUSK"]}
{"type":"seasonIn","seasons":["AUTUMN"]}
{"type":"betweenMinutes","start":1320,"end":120}
{"type":"all","conditions":[...]}
{"type":"not","condition":{...}}            // 新增，见 §四
```

`NpcTriggerCondition` 同构：`world{condition}` / `weatherBecame{kinds}` / `playerEnteredPlace{placeType}` / `playerMetNpc{npcId}` / `playerIdleFor{days}` / `playerMissedCommitment{npcId}` / `all`。

### 宽松解析（手写 JSON 的救命点）

- **枚举一律按名字解析，忽略大小写 + trim**：`entries.firstOrNull { it.name.equals(raw.trim(), true) }`。
- 解析失败的错误消息里**列出该枚举的全部合法值**。
- `WeatherKind` 额外接受简写 `"RAINY"` = `LIGHT_RAIN + HEAVY_RAIN`（代码里 `WeatherKind.RAINY` 是真实概念，用户一定会这么写）。
- 编码一律 UTF-8 无 BOM；读取时剥掉前 3 字节 BOM（记事本会加）。
- `Json { ignoreUnknownKeys = true; explicitNulls = false; prettyPrint = true }`，同一套 DTO 用于 encode/decode。
- **DTO → 领域对象的构造全部包在 `runCatching` 里**（[ResourceYieldRule.kt](file:///e:/DreamingPath/RainingTrace/app/src/main/java/com/rainingtrace/domain/world/ResourceYieldRule.kt#L30-L35) 的 `require`、`Place.init`、`WeatherIn.init`、`NpcProfile` 的 `favoriteTopic in topics` 等等）——**现有 invariant 自动变成一条 ERROR 诊断，而不是崩溃**，不用另写校验。

## 二、覆盖 / 合并语义（纯函数，可单测）

1. 读内置 8 份 → 建 id 索引。同文件内重复 id：后者胜 + ERROR（确定性）。
2. 用户层逐条：id 命中内置 → **原位替换**（保持渲染顺序稳定）；未命中 → 追加尾部。
3. `removedIds` / `removedKeys` / `removedAliases` → 从合并结果剔除；删不存在的 id = WARN（不报错）。
4. 引用完整性校验：`placeId` 悬空（NPC 作息 / 别名）、`resourceId` 悬空（产出规则）、`npcId` 悬空（主动规则）、`favoriteTopic ∉ topics`。
5. **降级粒度刻意不对称**：
   - 产出规则 / 地点 / 资源：**丢该条** + ERROR（加法内容，少一条不会说谎）。
   - NPC：**一条作息悬空 → 丢整位 NPC** + ERROR。半截作息的 NPC 会瞬移或永不离开上一处，那是"静默说谎"，比缺席更糟；缺席是响亮的（日志 + 诊断面板 + 单测）。
   - `NpcTrait` / `NpcTopic` 写错：只丢那一个成员，NPC 保留 + WARN（性格标签只影响语气）。

诊断模型 `ContentDiagnostic(level, file, entryId, message)`，`ERROR = 该条目被丢弃`、`WARN = 保留但可疑`。三个出口：

1. logcat tag `ContentLoad`，每条一行、带文件名与 entryId；
2. 设置页只读「内容（调试）」区：列出各类型条数 + 全部诊断（沿用 `SectionLabel` / `OptionRow` 惯例）；
3. 单测 `ShippedContentTest` 断言内置 8 份的 ERROR 数为 0 —— **这是"内置内容永不静默降级"的硬保证**，也是原编译期常量保证的替代品。

## 三、加载位置

**AppContainer 构造期 `runBlocking` 一次性加载**（对齐 [AppContainer.kt](file:///e:/DreamingPath/RainingTrace/app/src/main/java/com/rainingtrace/core/common/AppContainer.kt#L122-L129) 里 `gridManager` / `initialLocationMode` 的既有先例），之后靠 `reload()` 热更新。

不做懒加载 / 不做 `StateFlow.value + 兜底`：内容被地图、设置、聊天、背包同时需要，懒加载失手会表现为"莫名其妙空掉的地图"；`.value + 兜底` 会让启动窗口内 `nearby()` 返回空、地图先空后闪。

- `ContentStore(context)`：`loadBlocking()`（assets + 覆盖层）、`reload()`（重读覆盖层）、`index: StateFlow<ContentIndex>`、`diagnostics`。
- `ContentIndex` **持有已构建好的对象**（`placeRepository` / `resourceCatalog` / `yieldRules` / `npcRepository` / `proactiveRules` / `lines` / `aliases` / `keywords`），重载时整体重建 → 读取 O(1)。
- AppContainer 里 5 个薄委托（`data/repository/LiveRepositories.kt`，各约 8 行）读 `store.index.value.xxx`。**现有 `Fake*` / `InMemory*` 实现一行不改**，35 个既有测试保持绿。
- `[WorldClock]` 口径不变：不引入新的时间源。

## 四、`Not` 条件（含必须一起做的 specificity 修复）

[WorldCondition.kt](file:///e:/DreamingPath/RainingTrace/app/src/main/java/com/rainingtrace/domain/world/WorldCondition.kt) 新增：

```kotlin
data class Not(val condition: WorldCondition) : WorldCondition {
    override val weight: Int get() = 0        // 否定条件不是"更具体"
    override fun isSatisfiedBy(state: WorldState) = !condition.isSatisfiedBy(state)
}
```

同时给 `WorldCondition` 加 `open val weight: Int get() = 1`，[ResourceYieldRule.kt](file:///e:/DreamingPath/RainingTrace/app/src/main/java/com/rainingtrace/domain/world/ResourceYieldRule.kt#L42) 的 `specificity` 从 `conditions.size * 2 + …` 改为 `conditions.sumOf { it.weight } * 2 + …`。

不改 `NpcTriggerCondition.specificity`（它用自带的 1/2 常数，且其 `All` 是 `sumOf`，`Not` 的 weight 概念不适用）。`NpcTriggerCondition` 本轮不加 `Not`。

**语义必须在 KDoc 与 JSON 里写死**：`Not` 直接布尔取反，不做三值逻辑 —— `Not(SeasonIn(AUTUMN))` 在 `season == null` 时为**真**。这是唯一会让作者意外的点，加 `WorldConditionTest` 用例。

## 五、手机现场采点

新增 domain（纯 Kotlin，可单测）：

```kotlin
// domain/map/PlaceDraft.kt
data class PlaceDraft(val name: String, val type: PlaceType, val coordinate: WorldCoordinate,
                      val actions: Set<PlaceActionType>, val description: String = "")
fun newPlaceId(nowMs: Long, taken: Set<String>): String   // "place.user.<epochMs>"，撞车追加 "-2"
interface PlaceWriter { suspend fun addPlace(draft: PlaceDraft): PlaceWriteResult }
sealed interface PlaceWriteResult { data class Added(val id: String) : …; data class Rejected(val reason: String) : … }
```

**资源点不需要第二套 API**：`PlaceType.category == RESOURCE` 的地点就是资源点，UI 里用 `PlaceType` 选择器区分。

实现 `data/content/JsonPlaceWriter.kt`（需 Context，故在 data 层）：读 `filesDir/content/places.json`（不存在 = 空 entries）→ 追加映射后的 DTO → **原子写**（写 `.tmp` 再 `renameTo`）→ `store.reload()` → 返回 `Added(id)`。名称空 / 动作空 → `Rejected`，**不抛异常**。

`MapViewModel` 新增 `captureCurrentPlace(draft)`：成功 → toast + `refreshPlaces(coord)` + `selectPlace(id)`（**详情卡是即时确认的关键**：新点所在格若未揭示，`placeVisualsFor` 不会画它）。失败 → toast 原因。

**UX：本轮只做「把当前位置记成一个地点」按钮，不加长按落点。** `locationProvider.latest` 在 GPS 与 FAKE 两种模式下都有效（FAKE 模式下先点地图把玩家挪过去，这是既有语义，不该被夺走），完全不用改 [MapLibreAdapter.kt](file:///e:/DreamingPath/RainingTrace/app/src/main/java/com/rainingtrace/platform/map/MapLibreAdapter.kt)（它也没有长按支持）。长按任意落点（"坐在工位标点"）延后。
