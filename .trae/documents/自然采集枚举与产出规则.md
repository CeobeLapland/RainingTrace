# 自然采集：扩枚举 + 铺产出规则

## Context

你往 `resources.json` / `recipes.json` 里补了大量内容（现 511 资源 / 246 配方），但**产出规则只有 23 条**，只覆盖 10 个 NATURE 资源——剩下 105 种自然基材在游戏里根本采不到，整条"采集→合成"链是空转的。

要做成星露谷 / Minecraft 那种"走到地方顺手采"，需要三件事对齐：
1. **地点类型**能表达设计稿里的自然地点（松林、湿地、菜圃…），现在枚举里一个都没有；
2. **地点动作**能表达"拾取 / 收获 / 垂钓 / 取水"，现在只有「观察 / 采集」两个；
3. **产出规则**把 115 种 NATURE 基材一一挂到「地点类型 + 动作 + 条件」上。

本次只做自然采集这条线；人文室内类、校外类地点与动作等你采到经纬度后再批量加（设计稿 `assets/temp/places_design.md` 已备好 50 个 type / 139 个地点）。

**已定的口径**：4.1 只加户外自然 10 个 `PlaceType`（全归 PLACE 类）；4.2 新增 6 个动作；筛选面板改横向滚动。

## 四、铺产出规则（核心）

文件：[yield_rules.json](file:///e:/DreamingPath/RainingTrace/app/src/main/assets/content/yield_rules.json)

**目标：115 种 NATURE 资源每一个都至少被一条规则产出。**
- **现有 23 条一条不动**：其中 `rule.observe.rainy_lake` 被 `ShippedContentTest` 硬断言（条件必须是单个 `WeatherIn(kinds={RAINY})`），不能改名/删改。
- 设计依据：
  1. `places_design.md` 第四节各表的**「关联资源」列**是锚点（约 43 个资源直接对号入座：松林→pine_cone/pine_needle、稻田→rice_ear/crucian_carp、菜圃→potato…）；
  2. 其余按资源的 `tags` 归组（高频：farm / autumn / lake / rain / spring / wood / ore / summer / river / flower / night / pond / shell / feather / stone / forest / bamboo / pine / crystal / herb / winter…）；
  3. 稀有度决定条件数与数量：COMMON 保底 1 份、UNCOMMON 加 1 个条件、RARE 加 2 个条件且条件组合唯一。
- **动作与设计稿对齐**：规则的动作 = 设计稿给该地点标的动作（拾取类用 `GATHER`、收获类用 `HARVEST`、水边用 `FISH`/`WATER`、通用用 `COLLECT`、探索类资源用 `EXPLORE`）。`WATCH` 在自然地点里没用到，暂不写规则。
- **写法约束**（沿用现有风格）：
  - id 唯一，形如 `rule.<action小写>.<资源短名>`；
  - `placeType` 尽量填（具体度更高、语义更准），只有保底规则才留空；
  - 同一 `(action, placeType)` 下尽量让条件组合互不相同，避免"同权并列"；万一并列只会按 id 轮换（前者进冷却后轮到下一条），**不会丢资源**；
  - `cooldownMs` 沿用 `600000`（10 分钟），稀有 / 高价值用 `3600000`；
  - 条件合法值：`weatherIn(kinds)` / `timeOfDayIn(times)` / `seasonIn(seasons)` / `betweenMinutes(start,end)` / `all` / `not`；`WeatherKind = CLEAR|CLOUDY|LIGHT_RAIN|HEAVY_RAIN|SNOW|FOG|WIND`（`RAINY` 为简写），`TimeOfDay = DAWN|DAY|DUSK|NIGHT`，`Season = SPRING|SUMMER|AUTUMN|WINTER`。
- 预期新增 90~115 条，总数约 115~140 条。
