# RainingTrace / 雨迹 — 开发阶段、任务树与切片

## 1. 总策略

不要从“完整游戏”开始。

开发目标依次变成：

> **技术可运行 → 可玩的空间循环 → 有记忆 → 有现实感 → 有世界 → 有人物 → 有长期成长 → 有 AR 魔法。**

## 7. 每个任务的标准切片

### Example：RT-MAP-005

```text
Goal:
  Player can reveal nearby hex cells.

Input:
  playerHex
  revealRadius

Output:
  updated ExplorationState

Non-goal:
  no real GPS
  no backend sync
  no animation

Tests:
  radius 0
  radius 1
  negative radius rejected
  duplicate cells removed
```

## 8. 依赖规则

### 必须先做

```text
Domain model
 ↓
外部化 JSON 内容层（assets/content + 私有目录覆盖）
 ↓
UseCase
 ↓
UI
 ↓
Real platform adapter
 ↓
Remote sync
```

### 不允许反过来

不要：

```text
先把 Map SDK 接上
然后围着 SDK 设计整个游戏
```

## 9. 每阶段 exit criteria

### P0 Exit

- cold start 正常
- Fake mode 可玩
- map + fog 正常
- place action 正常
- resource/inventory 正常
- memory 正常
- one local AR object
- no critical crash

### P1 Exit

- auth
- sync
- economy
- NPC skeleton
- home
- basic event
- offline recovery

### P2 Exit

- async social traces
- world events
- anomalies
- history
- dynamic NPC

### P3 Exit

- scalable world backend
- production-grade geospatial AR
- city-scale operations
