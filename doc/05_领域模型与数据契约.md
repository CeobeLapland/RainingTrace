## 2. Event-first 原则

世界系统尽量记录“发生过什么”，而不是只保存“最后结果”。

例如不要只有：

```text
player.exploredCells = 108
```

而是同时保留事件：

```text
ExplorationEvent(cellId, timestamp, source)
```

这样可以生成：

- 足迹
- 年鉴
- 统计
- 时间线
- 成就
- 记忆
- 玩家世界图谱

同时可对事件做压缩/归档。

---

## 3. 事件的三种类型

### Local Event

只影响玩家自己。

### Regional Event

影响一个区域。

### World Event

影响所有玩家。

---

## 4. 状态与事件不要混为一谈

例如：

```text
Inventory = 当前真相
ItemAcquiredEvent = 历史
```

两者都需要。

## 6. 服务器权威命令

推荐 Command / Result 模式：

```text
Client Command
   ↓
Server validation
   ↓
Game rule execution
   ↓
Event append
   ↓
State projection
   ↓
Result
```

例如：

```text
POST /game/actions/gather

input:
placeId
resourceId
clientTimestamp
nonce

server checks:
- player authenticated
- within valid area
- place active
- resource condition
- cooldown
- nonce not replayed

output:
- grantedItems
- updatedStateVersion
- events
```

---

## 7. Idempotency

所有会产生奖励的写操作必须支持 nonce/idempotency key。

目的：

> 用户点两次、网络重试两次、App 崩溃重发两次，都不能凭空得到双倍奖励。

## 9. 六边形系统

业务层推荐 axial coordinates：

```text
q, r
```

不要直接使用浮点经纬度作为 cell identity。

映射：

```text
WGS84 lat/lng
   ↓
projection / hex indexing
   ↓
HexCellId
```

逆映射：

```text
HexCellId
   ↓
cell center / polygon
   ↓
map rendering
```

## 10. 时间系统

所有业务时间都通过：

```kotlin
interface WorldClock {
    fun now(): Instant
    fun localDate(zone: ZoneId): LocalDate
}
```

测试使用：

```kotlin
FakeWorldClock(instant = fixedInstant)
```

禁止在 UseCase 里直接：

```kotlin
Instant.now()
```

---

## 11. 随机系统

所有世界事件使用显式 seed：

```kotlin
interface RandomSource {
    fun nextInt(bound: Int): Int
}
```

生产环境可以来自 server seed；测试环境固定 seed。

这样：

> “昨天为什么出现这个事件”

能够被复现。
