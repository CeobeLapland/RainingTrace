# RainingTrace / 雨迹 — 地图、定位与 AR 专项

## 1. 地图的职责边界

地图只负责：

- render
- camera
- gesture
- visual layer
- location marker

地图不负责：

- 玩家资源
- 探索判定
- 任务奖励
- 金币
- 记忆
- NPC 逻辑

---

## 2. 六边形网格

建议 P0：固定边长/固定 resolution，先只做一个精度。

### P0

- axial coordinates
- deterministic cell id
- reveal radius
- neighborhood
- fog state

### P1

- 多 resolution
- 区域聚合
- 服务端空间索引

### P2

- 动态 biome
- world ecology overlay

---

## 3. 迷雾

状态建议：

```text
UNKNOWN
DISCOVERED
VISITED
MEMORIZED
SPECIAL
```

不要把“地图发现”和“玩家真正到过”混为一个 bool。

---

## 4. 定位

### 位置采样不是游戏事件

`LocationSample` → 经过过滤 → 才可能触发 `PlayerMoved`。

过滤条件：

- accuracy
- timestamp freshness
- horizontal jump
- minimum movement threshold
- stationary debounce

### 推荐事件层

```text
Raw Location
 ↓
Location Filter
 ↓
Stable Location
 ↓
Cell Mapping
 ↓
Exploration Rule
 ↓
Game Event
```

---

## 5. 避免“GPS 打游戏”

不要每次定位更新都：

> 发网络请求。

P0：

- 本地计算 cell
- 聚合 movement
- 批量同步

P1：

- 后台同步
- server validation

---

## 6. 路径/足迹

玩家足迹不是原始 GPS dump。

默认采用：

- 时间 bucket
- 空间 bucket
- Douglas-Peucker 或等价简化
- 精度等级
- visibility policy

目标：

> 保留“你去过哪里”的感觉，而不是记录一份高精度监控轨迹。

---

## 7. 地图 POI 分层

```text
Layer 0: Real Places
Layer 1: Game Places
Layer 2: Resources
Layer 3: NPC
Layer 4: Events
Layer 5: Memories
Layer 6: Social Traces
Layer 7: AR Anchors
```

UI 支持开关。

默认不要全开，否则世界会变成“图标汤”。

---

## 8. MapAdapter

建议接口：

```kotlin
interface MapRendererAdapter {
    fun setCamera(camera: MapCamera)
    fun renderCells(cells: List<CellVisual>)
    fun renderPlaces(places: List<PlaceVisual>)
    fun renderPlayerMarker(marker: PlayerMarker)
    fun clearLayer(layer: MapLayer)
}
```

不要把 `MapView` 暴露给 Domain。

---

## 9. AR 架构

```text
AR Feature
   ↓
ARController interface
   ↓
ARCoreAdapter
   ↓
AR Session
```

Domain 只处理：

```text
ArObject
- id
- assetId
- anchorType
- worldCoordinate
- interactionProfile
```

---

## 10. AR 阶段

### AR-0：Local AR

- 平面检测
- 点击放置
- 一个虚拟物件
- 无世界定位

### AR-1：地点 AR

- 现实地点附近出现虚拟物件
- 基于 GPS + local orientation
- 允许误差

### AR-2：Geospatial AR

- WGS84/Terrain/Rooftop anchor
- VPS
- 大规模地点绑定

Google ARCore Geospatial API 已支持通过 GPS、设备传感器与 VPS 建立地理空间定位，并提供地理 anchor。citeturn765638search3turn765638search15

---

## 11. AR 必须支持失败

所有 AR feature 必须设计：

```text
SUPPORTED
INITIALIZING
READY
TRACKING_LOST
UNSUPPORTED
PERMISSION_DENIED
ERROR
```

任何状态都不能把用户卡死在黑屏相机页面。

---

## 12. 相机/随手拍

CameraX 负责：

- capture
- preview
- image metadata
- orientation

业务层拿到：

```text
CapturedMedia
- localUri
- capturedAt
- locationOptional
- orientation
- mimeType
```

照片分析、标签和资源识别再走后续 pipeline。

---

## 13. “随手拍”处理流水线

```text
Camera
 ↓
CapturedMedia
 ↓
Local Draft
 ↓
Optional On-device preprocessing
 ↓
Upload
 ↓
Vision / classification (optional)
 ↓
Game interpretation
 ↓
Memory / Resource / Discovery
```

必须允许用户先保存照片，再慢慢处理。

---

## 14. 地图性能

禁止一次渲染整个城市所有实体。

使用：

- viewport query
- zoom-level filtering
- clustering
- tile/region based loading
- local cache

---

## 15. 第一版只覆盖“小而密”的区域

建议：

> 一个校园 / 大学园区 / 高密度可步行社区。

不是城市级全地图。

因为《雨迹》最重要的是：

> 一个地方里“有什么”。

不是：

> 地图有多大。
