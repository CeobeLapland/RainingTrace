# RainingTrace / 雨迹 — 本地开发与运行手册

## 1. 开发环境

建议：

- Android Studio 当前稳定版
- JDK 使用项目 Gradle/Kotlin 支持的版本，以 `gradle/libs.versions.toml` 和 Android Gradle Plugin 官方要求为准
- Android SDK
- Git
- Docker（Supabase CLI 本地运行 Edge Functions/服务时需要）
- Supabase CLI

不要在文档里硬编码“永远使用某一个小版本”。依赖版本以仓库 lock/versions catalog 为准。

- **运行不是虚拟机，是我的真机，注意安全问题**
---

```bash
git clone <repo>
cd rainingtrace

./gradlew test
./gradlew assembleDebug
```

然后：

```text
Android Studio
```

## 3. Fake Mode

**没有 `BuildConfig.FAKE_WORLD` 这个开关**（旧稿写过，从未实现）——现在是设置页里的一组运行时开关：

- 定位方式：`Fake`（点击地图移动，不申请定位权限）/ `GPS`
- 时段、季节、天气：设置页「世界状态（调试）」可固定成任意值
- NPC：设置页「NPC（调试）」可把 NPC 的时间偏移 ±1/3/6/12 小时
- 内容：不需要 fake——内容本来就全部来自外部 JSON（见下）

Fake mode 的目标：

> 开发者没有手机、GPS、网络，也能做 80% 的 P0 开发。

**内容不在代码里**：地点 / 资源 / 产出规则 / NPC / 主动规则 / 台词 / 别名 / 关键词
都在 `app/src/main/assets/content/*.json`。要改就放一份同名文件到
`<filesDir>/content/`（`adb push` 即可），再在设置页点「重新读取内容」——
不用重编译、不用重装。**不要**去改 Kotlin 常量：那是已经拆掉的"第二份真相"。

## 4. 环境变量原则

### Client-safe

可以通过公开配置注入的：

- Supabase URL
- publishable/anon key（按 Supabase 当前安全模型使用）
- map style URL / public tile configuration

### Secret

绝不能进 APK：

- service role key
- server secret
- AI provider secret
- private tile credentials
- admin credentials

Supabase 的客户端鉴权和 RLS 应承担用户级数据访问控制；Edge Functions 的 secret 用服务端环境变量保存。citeturn765638search8turn765638search0

## 5. 推荐 .env 示例

```dotenv
# client-safe / build-time
SUPABASE_URL=
SUPABASE_PUBLISHABLE_KEY=
MAP_STYLE_URL=

# server-only; never packaged into Android
OPENAI_API_KEY=
SUPABASE_SERVICE_ROLE_KEY=
PRIVATE_TILE_KEY=
```

实际项目分开保存：

```text
.env.local
.env.production
supabase/.env
```

不要提交。

## 7. 数据迁移

所有 schema 修改必须：

```text
migration.sql
```

禁止：

> “我直接在 Dashboard 改了，因为比较快。”

Dashboard 可以用于观察、测试，正式变化必须进 migration。

---

## 8. 日志规范

开发日志：

```text
[RT][MAP]
[RT][LOC]
[RT][WORLD]
[RT][MEMORY]
[RT][AR]
[RT][SYNC]
```

不要写：

- 完整 GPS 原始坐标
- access token
- secret
- 私人照片 URL（必要时打 hash/id）

---

## 9. 断网测试

每个 P0/P1 功能至少一次：

```text
启动在线
→ 进入地图
→ 断网
→ 执行动作
→ 恢复网络
→ 同步
```

必须检查：

- 是否重复奖励
- 是否丢记忆
- 是否状态覆盖
- 是否出现死循环 retry

---

## 10. Android 权限

原则：

> 需要时再请求，而不是首次启动一次请求所有权限。

P0 可能涉及：

- location
- camera

AR/后台定位等权限进入对应功能时再申请，并提供拒绝后的降级体验。
