## 0. 本版变更摘要（v1 → v2）

1. **重心叙事调整（不删内容）**：把"生活记忆 与 神秘异常 对半"改为"生活为本体、神秘为钩子（约七三）"。异常/传闻/历史地图从"主线目标"降维为"长期钩子 + 调味"，但全部内容原样保留。
2. **新增「真实信号接入」系统**：真实天气、真实季节日照、校园实时小信号优先接入；本地模拟兜底，可配置、可离线。
3. **新增「实拍识别与相机系统」**：相机从"工具升级线的一项"升级为一等公民系统，拍植物解锁植物图鉴、拍老建筑解锁历史层、传闻靠"拍到证据"证实。
4. **新增「地点微仪式 / 轻交互」系统**：给地点加一次性轻仪式，低成本生成记忆与足迹。
5. **强化「可变世界」的可感知性**：软肉鸽不再只悄悄重排，配合真实信号让"今天和昨天不同"被玩家看见；「今日世界播报」由 P2 提至 P1 作为载体。
6. **「轻社交」优先级前移**：仍在 P1，但在 P1 内排序提前，作为"现实被众人共同书写"的具身增强。
7. **新增「AR 系统」**：主线三种（宠物/友善生灵、虚拟 NPC、异常/传闻），低优先级两种（记忆重现、过去地图叠加）。第一版不实现，专案预留接口与数据占位，后期做"AR 观察窗"验证。
8. **技术方向更新**：AR 走双轨——ARCore（设备端锚定/平面跟踪）+ CameraX/IMU（无 GMS 伪 AR 叠加），两条路线都做验证，不因课设演示限制而提前放弃任何一条。

## 1. 概述与愿景

### 1.1 背景

这是一门移动互联系统的课设，选题自由度高。灵感来自《星露谷物语》，但目标不是做一款"移动版星露谷"，而是把《星露谷》里那种"经营一块属于你的地方、自己决定怎么过"的感觉，迁移到现实地理空间上。

《星露谷》的核心体验可压缩为一句：你拿到一块荒地，投入时间与体力，把它变成属于自己的家。本项目对应：你走进一座真实的校园，投入真实的脚步与注意力，把它变成属于自己的世界。

### 1.2 一句话定位

> 一款基于现实地理空间的生活模拟 RPG：玩家通过真实行走解锁地图迷雾，把经过的地点、天气、人物与事件记录成"我的世界"，在探索的基础上养成、种田、建设、和虚拟人物动物互动，并在表层生活之下逐步触达传闻、异常与历史地图。
>
> 即：**生活记录 + 探索 + 养成建设 + 世界互动 + 软肉鸽 + 轻社交**。其中"生活记录"是本体，神秘内容（传闻/异常/历史地图）是其上的调味与长期钩子。

"世界互动"是一个综合概念，在本项目中对应 NPC 对话与关系、宠物/友善生灵、节日、地点微仪式、实拍识别、AR、轻社交等多条与"世界"发生关系的通道，而非单一系统。

### 1.3 核心卖点

> 每个人，都生活在属于自己的开放世界里。

副卖点：**你的世界会跟着真实世界一起变天、变季、变人；你越认真生活，它越鲜活。**

### 1.4 与《星露谷》的继承与放弃

**继承**

- 开放式玩法：不强制单一目标，玩家自由选择"农场主 / 钓鱼佬 / 矿工 / 社交达人 / 装修狂 / 记录者"式的个人路线。
- "每天做点什么"的节奏感：用有限的时间与体力做资源分配。
- 生产与建设：采集、种植、钓鱼、加工成更高价值的产物。
- 收集图鉴：把零散玩法串起来的主线。
- NPC 关系：好感度驱动的剧情解锁。
- 季节与节日：周期性刷新世界状态。

**放弃 / 改造**

| 星露谷 | 本项目 |
| --- | --- |
| 体力条 | 现实中真实的时间与体力 |
| 金币 | 探索量、记忆、纪念币、声望 |
| 虚拟农场 | 真实的校园地图 |
| 战斗与怪物 | 异常、传闻与调查 |
| 主线任务 | 世界图鉴 + 记忆节点（生活本身） |
| 田间种植 | 我的空间里的种植台 / 养鱼池，由天气与步数驱动 |
| 游戏内天气 | 真实天气优先，本地模拟兜底 |

## 2. 核心概念与已拍板决策

以下决策已确定，是后续设计的前提：

1. **主灵魂 = 生活记忆为主（约七三），神秘异常为长期钩子**，用"双层世界"统一。异常是玩家认真生活、走得够深之后"它自己来找你"的馈赠，而非强迫达成的主线目标。
2. **地图基底 = 真实坐标 + 虚拟叠加层**：真实校园地理为骨，其上叠加虚拟异常、传闻、历史第二张地图。
3. **第一版范围 = 单一校园**（校内有湖，满足钓鱼前提）。
4. **玩家可配置优先**：单机/多人、定位精度与策略、NPC 是否接外部 API、真实信号是否接入，均由玩家自行配置（贯穿全篇）。
5. **真实优先、模拟兜底**：一切能取自现实世界的信号（天气、季节、日照、校园动态），优先接真实数据；外部不可用时自动降级到本地模拟，绝不因断网/缺 key 而中断游戏。

### 2.1 双层世界机制

- **表层（生活 / 记忆）**：白天、真实天气、真实地点、NPC 作息、生产建设、日记图鉴。
- **深层（异常 / 神秘）**：在"深夜 / 下雨 / 特定日期 × 特定地点"翻面，出现传闻证实、历史第二张地图、异常事件。
- **记忆是钥匙**：探索度、图鉴完成度、NPC 熟悉度越高，越能看见表层之下的异常。

这一机制把"记忆"和"异常"变成一条因果链：先好好生活，才能看见生活底下藏着什么。异常是生活的馈赠，不是生活的前提。

### 2.2 探索四层结构

1. **现实**：我走到了一个地方。
2. **发现**：我发现了这个地方。
3. **故事**：我发现了这个地方背后的历史与人物。
4. **传说**：我发现了一个不知道是否真实的东西。

## 3. 核心游戏循环

### 3.1 主循环

```text
现实生活
   ↓
去某个地方（真实行走）
   ↓
发现新的东西（地点 / 资源 / 人物 / 事件）
   ↓
获得「知识 / 物品 / 记忆」
   ↓
解锁新的线索
   ↓
去探索新的地方
   ↓
形成自己的故事
   ↓
写入「我的世界」
   ↓
继续生活
```

### 3.2 探索与养成的闭环

探索与养成不是两条线，而是一条焊死的环：

```text
探索采料 → 养成(建造/工具/图鉴/生灵) → 能力变强 → 更深探索
```

探索产出原料，养成把原料变成可见的成长（家变大、工具变强、图鉴变满），更强的能力反过来解锁更深的内容。这是《星露谷》核心闭环在现实地理上的移植。

### 3.3 与传统 RPG 的区别

传统 RPG 循环是`接任务 → 打怪 → 得经验 → 升级`，数值驱动。本项目循环是`生活 → 探索 → 发现 → 记录 → 解锁 → 再探索`，由玩家真实的脚步与选择驱动。

### 3.4 玩家的"一天"

出门前看一眼今日世界播报，决定今天去哪、做什么（采集、钓鱼、拜访 NPC、追一条传闻、纯散步记账、到某处拍张照）。一天的收益沉淀为地图探索度、图鉴条目、记忆节点与关系进展，而非一串金币。

## 4. 设计原则

1. **记录生活，而不是命令生活**。不设计"每件事 +XP"。
2. **世界是活的**。同一地点在不同时间、天气、季节就是不同的地点。
3. **密度优先于规模**。先做透一个校园。
4. **真正的成本是时间与探索量**。稀缺资源是玩家的注意力与脚步。
5. **系统之间互相咬合**。孤立玩任何一个系统都会有缺口，需要用别的系统来补。
6. **内容数据驱动**。地图、NPC、任务、资源、事件、养成全部是配置/数据，代码只是读取引擎。这是自定义模式与可扩展性的前提。
7. **养成不膨胀数值**。养成提供"不确定的收集乐趣 + 可见成长"，不靠金币与战斗膨胀。
8. **真实优先、模拟兜底**。能接真实信号的（天气、季节、日照、校园动态），优先接；接不了就本地模拟，外部失败绝不中断游戏。这是本项目区别于纯虚拟游戏的根本。

## 5. 世界观与设定

### 5.1 地图 = 一所大学

一所校园天然具备构成小型开放世界的要素：建筑、道路、NPC、社团、商店、宿舍、食堂、隐藏角落、真实历史与传闻。第一版全部内容落在这所学校内，玩家以真实定位移动。

### 5.2 时间维度（两层）

- **现在地图**：玩家日常所在。
- **过去地图**：收集足够历史资料后解锁，展示同一地点的过去样貌（现实中已消失或改建的建筑出现于此）。

第一版只做两层，不展开多时代。

### 5.3 历史与档案

校园真实历史（老照片、建成年份、曾用名、变迁事件）与虚构传闻混合，构成深层内容素材。内容设计时明确标记哪些是史实、哪些是虚构，避免误导。

## 7. 核心系统

### 7.1 地理与迷雾（世界认知系统）

玩家初次进入，地图大部被迷雾覆盖。迷雾不是简单的地图解锁，而是"对世界的认知"，玩家真实行走后，道路、地点、历史、NPC、事件、传闻、他人足迹随之显现。

- 地图基底用开源免费瓦片（OpenStreetMap 方向）。
- 迷雾用六边形格子拼合，进入某格半径后解除。
- 迷雾分层显现：先地点，再历史，再传闻，再异常线索。
- 定位精度、定位时间、耗电策略做成玩家可配置项。

### 7.2 地点系统

每个可识别地点是一等公民，拥有独立档案：名称、坐标、类型、建成/改建年份、曾用名、一段可解锁历史、关联的资源点和事件、玩家首次发现时间与个人记忆节点。发现即触发"[发现]"并写入地点图鉴。

### 7.3 时间 / 天气 / 季节 / 世界状态（真实优先）

这些因素直接改变可玩内容，且**优先取自真实世界信号**（详见 7.28）：

- 天气：雨天限制部分 NPC 出现、产生积水点、触发特定资源（雨后蘑菇）与事件。真实天气优先，本地模拟兜底。
- 昼夜：夜晚地图"变脸"，仅夜间出现地点 / NPC / 传闻 / 异常。
- 季节：季节点只在对应季节可采集，作物与鱼种随季节轮换。
- 世界状态由"当前时间 + 天气 + 季节 + 玩家进度"共同决定。

### 7.4 探索与足迹

记录玩家走过的路线，不做运动 App 定位：

- 展示探索覆盖度、本周步数、新发现地点数。
- 落点是"我在这世界留下的痕迹"，并与历史层、他人足迹对照。
- 连点成线形成"路线"，触发轻量成就。

### 7.5 采集（亲临资源点）

真实校园的自然与人文载体是资源点，须亲临才能采集：

- 自然点：湖/河、花坛、草坪、老树、树林。
- 人文点：老建筑、石碑、雕塑、涂鸦墙、牌匾。
- 季节点：樱花只在春天、银杏只在秋天。

采集物归入六类资源，种类随季节、天气、昼夜变化。大部分"先别卖"，图鉴、加工、NPC、传闻解锁都会用到。

### 7.6 种植（我的空间 · 种植台）

玩家在"我的空间"放置种植台，把探索获得的种子种下：

- 生长进度 = 真实时间 + 真实天气 + 玩家今日探索量。
- 下雨且步数高时作物进度额外增长，形成"走路=浇水"隐喻。
- 成熟后进加工链或图鉴捐赠。

### 7.7 钓鱼与养鱼

校园有湖，作为钓鱼点存在。钓鱼小游戏延后，当前用"种鱼/养鱼"为主：

- 钓鱼获取鱼苗，返回"我的空间"放入鱼池继续养成、繁殖，可出稀有。
- 保留钓鱼为获取鱼苗的轻交互（非占主玩法）。
- 鱼图鉴作为记忆图鉴的一类，稀有鱼限定"下雨的傍晚"等条件出现，接入传闻层。

### 7.8 加工与简化产线

对应星露谷"作物 → 加工品 → 更高价值"，但产线只做简化版：

- 有限的机器种类，例：腌菜罐→纪念罐、蜂箱、复制机等。
- 玩家摆放机器，手动或定时进料出料，材料自动流转一次。
- 不做自动化路由、管线、复杂红石逻辑，避免滑向工业自动化游戏。

产物坚定克制：不进金币，而是进三类用途——送 NPC 提升关系、捐图鉴/挂墙沉淀记忆、作钥匙解锁传闻或异常。

### 7.9 建设与自由建造（我的空间）

玩家空间采用网格化自由摆放，具备 Minecraft 式建造自由度：

- 探索采集的木/石/砖作为建材，扩建房间、摆机器、铺物件。
- 空间是"现实冒险博物馆"，不是单纯仓库。
- 建设与玩法挂钩：升级加工台才能加工，升级地图桌才能查看过去地图。

### 7.10 工具升级线

把星露谷"锄头→铜→铁→金"映射成探索工具，用探索材料升级，反哺探索效率：

- 地图探测器：扩大迷雾解锁半径。
- 采集篮：扩容。
- 钓鱼竿：提升获取鱼苗效率。
- 相机：解锁更多记忆节点与图鉴能力。（v2：相机能力独立强化为「实拍识别与相机系统」，见 7.29，本项不再只是"工具的一项"）
- 夜行手电：延长夜间探索能力。

这是把探索与养成焊死的关键系统。

### 7.11 宠物 / 友善生灵

校园里发现的友善生灵（野猫、鸟、松鼠）可"领养"回"我的空间"，进行电子宠物式养成：

- 喂食、互动、培养感情。
- 稀有生灵构成收集目标。
- 补上动物养成这条缺口，完全不涉及战斗。
- 一个被领养的生灵同时是一个记忆节点。

**v2 补充（AR 呈现，属 7.31 主线之一）**：后期在相机视野里，被领养的（或未被领养的）友善生灵可真的出现在真实环境位置，可靠近、可喂食、可互动，实现"宠物真的在这里"的临场感。此为 AR 主线内容，第一版不实现。

### 7.12 稀有变异收集

作物、鱼、生灵在特定条件下触发"稀有变异"：

- 条件示例：雨夜浇水、特定季节、特定地点采集。
- 稀有产物进收集图鉴支线，制造"再来一次"的动力。

### 7.13 日记与记忆节点

项目定位中的"灵魂系统"：

- 任一时间地点记录文字与照片，生成带坐标、时间戳的记忆节点。
- 节点落在地图，未来走过时触发"你曾经来过这里"。
- 记忆节点既是个人收藏，也是进入深层的进度依据。

**v2 补充（记忆重现，属 7.31 低优先级）**：后期在相机视野里，回到当年记录记忆的地点，可重现当年那张照片/场景的叠加，形成"时间胶囊"式的临场回望。此功能写入文档但优先级放低，第一版不实现。

### 7.14 世界图鉴

收集的是"对世界的认知"，是结构性主线：

- 地点图鉴、自然图鉴、人物图鉴、历史图鉴、传闻图鉴、知识图鉴、记忆图鉴。
- 完成度反向决定深层可见度（记忆是钥匙）。

### 7.15 资源与货币

资源六类：

1. **物质 Material**：食物、植物、矿物、手工物、地图碎片、收藏品。
2. **知识 Knowledge**：地点与历史的信息。
3. **记忆 Memory**：个人经历与记忆节点。
4. **文化 Culture**：当地传说、老建筑、历史人物、地方食物、节庆。
5. **足迹 Trace**：自己走过的路线。
6. **故事 Story**：地点 + 人 + 时间 + 历史 + 行为组合而成的高级产物。

货币定为三币制，各管一摊，避免刷分：

- **探索量**：进度门槛、解锁钥匙。
- **纪念币**：兑换、装饰、自定义内容。
- **声望**：社交、购买线索。

交易层面优先做信息经济（交换线索、发布发现换声望），不做金币驱动的经济模拟器。

### 7.16 NPC 与熟悉度

NPC 是"世界的记忆载体"，价值在于揭示世界观，而非派发采集任务：

- 每个 NPC 有作息表，叠加少量随机变化。
- 关系层级：陌生人 → 见过几次 → 认识 → 熟悉 → 朋友 → 知己，靠共同经历、帮助、对话、交换信息、分享记忆推进。
- 双轨配置：默认使用预设对话（兜底，离网可玩）；玩家可选择接入自己的 API 定制 NPC 表现（仅作增强）。
- 需统一 NPC 配置 schema，保证两条轨共用同一数据结构。

**v2 补充（AR 呈现，属 7.31 主线之一）**：后期在相机视野里，NPC 可站在其作息对应的真实地点，玩家举起镜头即可近身对话互动，而不仅是地图上的头像点。此为 AR 主线内容，第一版不实现。

### 7.17 随机事件

提供"今天不知道发生什么"的探索欲，不做纯 Roguelike：

- 分档：普通（下雨）、少见（彩虹）、稀有（角落遇见狐狸）、极稀有（流星雨）、神秘（某地点出现未知标记）。
- 事件作为引子，把玩家导向地点 / NPC / 传闻 / 异常。

### 7.18 传闻系统

地图出现"传闻"标记，玩家获得一条未证实信息，据此在特定时间地点蹲守，可能落空也可能触发真实内容。这是轻量"现实都市传说 / ARG"玩法，也是深层入口。扑空是合法结果。

**v2 补充（AR 呈现，属 7.31 主线之一）**：后期在相机视野里，"夜声""无字雕像"等传闻内容可具身化出现，蹲守与证实从"文字判定"升级为"视觉事件"。此为 AR 主线内容，第一版不实现；其"拍到证据"的轻量先行形态见 7.29。

### 7.19 世界异常（特殊任务）

深层内容核心载体，但并入统一任务池，作"特殊任务"标签，与 NPC 任务共用一套任务数据结构：

- 触发条件 = 时空条件 + 探索度门槛，而不是无限接取。
- 异常不是战斗，而是调查：拍照、收集线索、找 NPC、拼历史，最终解决。
- 解决异常可解锁过去地图碎片或深层传闻。
- 支撑机制同样覆盖 NPC 任务，避免为异常另起炉灶。

**v2 补充（AR 呈现，属 7.31 主线之一）**：后期异常调查的"现场"可在相机视野里具身化呈现，玩家在真实地点看到异常线索叠加。此为 AR 主线内容，第一版不实现。

### 7.20 历史第二张地图（时间维度）

收集足够历史资料后，切换到"过去地图"，看到同一地点的过去样貌。第一版仅两层（现在 / 过去）。

**v2 补充（过去叠加，属 7.31 低优先级）**：后期在相机视野里，站在老建筑前可看到其过去样貌的轮廓叠加。此功能写入文档但优先级放低，第一版不实现。

### 7.21 轻社交（非实时，玩家可配置，优先级前移）

非实时、低压力，强调"现实世界被很多人共同书写"。本版将其在 P1 内排序前移，作为"现实被众人共同书写"的具身增强：

- 漂流瓶：在真实地点留消息，后来者发现并回复。
- 玩家足迹：地图浮现其他玩家路线。
- 共享记忆：某地点查看"过去 30 天有 N 人记录"并浏览他人影像。
- 玩家可配置：单人模式不显示他人内容；多人模式才显示漂流瓶、足迹、共享记忆。

### 7.22 节日（校园真实节点）

开学、樱花季、银杏季、毕业季作为周期性事件，触发限定资源、NPC 聚集、限定内容。由人工维护配置。

### 7.23 职业 / 生活方向

角色由玩家的真实行为塑造：

- 方向示例：自然探索者、历史学者、记录者、探险家、生活家、漫游者。
- 玩家行为取向自然提升对应能力（探索历史 → 历史研究能力提升）。
- 优先级偏低，可延后。

### 7.24 今日世界播报（每日钩子，P2 → P1）

每天一句动态播报，如"旧礼堂今天在下雨""傍晚的湖面有传闻"——本版升级为"世界变异可感知"的主要载体（见 7.26），并结合真实信号（见 7.28）生成，构成日常回访理由，替代打卡签到。

### 7.25 成长 / 探索度（替代等级）

不做 Lv / XP，改以探索度与世界观呈现：校园探索度、已发现地点/历史/人物/传闻/记忆数量；世界观随探索越来越完整。

### 7.26 可变世界与周期洗牌（可玩性支柱，强化可感知）

地图固定是最大风险，用三层解法维持可玩性：

1. **周期洗牌（软肉鸽）**：每个学期/季节周期，传闻、异常、资源点位置、NPC 作息随机重排，玩家带已有进度进"新的一季"；每日再给一个"随机线索组合"当随机种子。轻量，不做死亡重开。
2. **你的地图因你而变**：记忆是钥匙 + 足迹 + 记忆节点，使同一地图每个玩家看到的内容不同，地图随玩家经历持续改写。
3. **UGC 可变地图**：玩家自建/自定义地图、NPC、内容，图本身不再固定（见 7.27）。

**v2 强化（可感知）**：洗牌与随机种子不再"悄悄发生"，而是通过今日世界播报、真实信号、随机事件的组合，让玩家明确感到"今天的世界和昨天不一样"（例：某天全校是"雨天 + 银杏提前黄 + 湖面有传闻"的奇异组合）。洗牌是机制，播报是它的"显影"。

### 7.27 开发者模式 / 自定义模式

新增核心功能，把内容生产变成玩法的一部分，并直接补足"内容不够、地图固定"的缺口。其架构前提是第 4 节第 6 条：**一切内容数据驱动**——地图、地点、NPC、任务、资源、事件、养成配方、异常、传闻全部是配置/数据表，编辑器只是这些数据的可视化入口。

**开发者模式（课设组用）**

- 可视化编辑地图元素、人物、任务、养成内容、事件时序。
- 导出为世界数据。
- 同时作为录入校园内容与答辩演示的工具。

**自定义模式（玩家用）**

- 改"我的空间"外观与布局。
- 自定义 NPC（接入自己的 API）。
- 导入 / 切换主题地图包。
- 调规则：定位精度、单机/多人、真实信号开关。

**范围与阶段**

- 第一版先做开发者可视化编辑器（客观需要录入内容）。
- 玩家自定义模式做轻量（外观 + 接 API + 切主题包）。
- 完整 UGC 与分享放后期。

### 7.28 真实信号接入（新增）

> 目标：让"现实感"来自真实的现实，而不是更多虚拟系统。这是本项目区别于"日记软件 + 种田游戏"的关键补丁。

三个信号源，全部可配置、可离线兜底，遵循"真实优先、模拟兜底"：

1. **真实天气**：接入真实天气数据（`WeatherSource` 接口，v1 已预留），优先级为"真实天气 > 按季节本地模拟"。玩家可关闭真实天气回退到模拟。
2. **真实季节与日照**：随真实日期推进季节判定（樱花季、银杏季各自对齐真实物候）；日出日落时间随真实纬度/日期变化，进而影响昼夜玩法持续时长。
3. **校园实时信号（可选）**：社团活动、食堂档口、公告、临时施工等校园动态作为轻量信号，注入今日世界播报与随机事件的"钩子"；这部分最难自动化，第一版可先由人工维护配置兜底，接口留好。

约束：外部信号获取失败/无 key 时，一律降级到本地模拟，绝不中断游戏（与 docs 的"先做本地可玩兜底"原则一致）。

### 7.29 实拍识别与相机系统（新增）

> 目标：把"拍照"从工具升级线的一项，升级为贯穿探索、图鉴、传闻的"一等公民"，在不动 AR 技术的前提下，先把"举起镜头"的第一人称在场感做出来。

- **拍植物 → 植物/自然图鉴**：对现实里的花、树、草坪拍照，匹配对应图鉴条目完成收录。
- **拍老建筑 → 历史层解锁**：对老建筑/石碑/牌匾拍照，解锁该地点的历史层内容。
- **传闻要靠"拍到证据"证实**：传闻从"蹲守判定"升级为"在现场拍到对应证据"才算证实（扑空仍是合法结果），这是 AR"视觉事件"的轻量先行形态。
- **与记忆节点打通**：实拍图天然可沉淀为记忆节点的照片。

范围约束与实现策略：**第一版只做"对图鉴/地点档案已知条目的本地匹配"（把拍到的地点、物体与已有内容 id 对上），不做通用图像识别模型**。通用识别（任意物体识别）成本与合规风险高，明确不纳入第一版。

### 7.30 地点微仪式 / 轻交互（新增）

> 目标：地点不止"走到 = 判定发现"，而是可以"做点什么"，用低成本动作制造高情感记忆。

给地点加一次性/低频轻仪式，生成记忆节点、足迹或图鉴条目，喂给"生活记录"这个灵魂：

- 在湖边"坐一会儿"：生成一条静默记忆节点。
- 在礼堂前"拍张照"：生成带地点的记忆 + 解锁/确认历史层。
- 在银杏树下"捡一片叶子"：获得季节采集物。
- 在老树前"看一会儿"：触发一条地点背后的短故事。

原则：轻仪式不占用主循环、不做数值膨胀，只负责"我在这里留下了点什么"的情感落点，与 7.4 足迹、7.13 记忆节点、7.14 图鉴自然咬合。

### 7.31 AR 系统（新增，P2 后期）

> 定位：AR 是"现实互动感"的高级解药，把"地图图标"升级为"相机视野里的身体在场"。它是一件**手段**，搭载在不同玩法之上，而不是一个独立的新玩法。第一版不实现，专案预留接口与数据占位，后期先做"AR 观察窗"验证。

#### 7.31.1 承载内容分层

**主线 AR（三种，团队已拍板要做）**

| 内容 | 说明 | 备注 |
| --- | --- | --- |
| 宠物 / 友善生灵 AR | 被领养/未领养的生灵出现在真实环境位置，可靠近、喂、互动（呼应 7.11） | 生活化、低成本、情感浓度高，2D 贴片即可 |
| 虚拟 NPC AR | NPC 站在作息对应的真实地点，举手镜头近身对话（呼应 7.16） | 把"地图头像"变成"面前的人" |
| 异常 / 传闻 AR | 传闻与异常线索在相机视野具身化出现（呼应 7.18/7.19） | 戏剧性最强，作为少数高光时刻，克制使用 |

**低优先级 AR（两种，写入文档但不率先实现）**

| 内容 | 说明 |
| --- | --- |
| 记忆重现 AR | 回访时重现当年照片/场景叠加，形成"时间胶囊"（呼应 7.13） |
| 过去地图叠加 AR | 老建筑前看到过去样貌的轮廓叠加（呼应 7.20） |

#### 7.31.2 技术双轨（两条都验证）

本项目课设环境对演示无硬性限制，因此 **ARCore 与 CameraX/IMU 两条路线都做验证**，不做"为了能演示而只走低配"的妥协：

- **路线 1 · ARCore**：官方 Android AR SDK，具备平面检测、设备相对锚点、光照估计等能力。依赖 Google Play Services for AR 与设备白名单，部分机型/环境不可用。
- **路线 2 · CameraX + IMU 伪 AR 叠加**：相机预览 + 陀螺仪/磁力计 + 透视投影做叠加，无 GMS、可离网、全设备可跑；缺点是无平面检测、无稳定锚点，会漂移，用"面向相机的 2D 贴片（billboard）"补偿稳定感。

结论：后期各做一个"AR 观察窗"最小验证点（同一地点 + 同一虚拟物），实测两种路线的设备覆盖、漂移与体验后，再定主方案与取舍。两者本质都只改表现层视图，共享同一份 `DerivedState` 输入。

#### 7.31.3 架构与数据衔接（关键，务必与 docs 对齐）

- **AR 只是表现层（`ui/`）的一个可选视图**，不进入领域层。输入 = 触发引擎算出的 `DerivedState`（"该地点此刻应出现哪些虚拟物"），本质是把叠加层从"俯视地图 Canvas"换成"第一人称相机视口"。
- **数据模型按数据驱动原则加可选字段**：`place / item / npc / creature` 增加可选的 `ar` 字段（如 `asset`、`anchor_mode`、`scale`、`billboard`、可选 `lat/lng` 锚定），缺失即不进 AR，向后兼容（`ignoreUnknownKeys`）。
- **资产策略**：优先 2D billboard 精灵图（宠物、植物、标记物适用），少数主角用低模 3D 占位；团队无美术，走生成/开源/占位资产，不在第一版投入建模。

#### 7.31.4 分期

- **MVP（P0）**：一行 AR 不写，仅保留 `ar` 可选字段占位 + `ui/` 下的 AR 视图接口占位，确保后期接入不推翻重来。
- **P2 后期**：先做"AR 观察窗"单点验证 → 视结论铺开主线三种 → 低优先级两种再评估。

## 8. 玩家第一周体验（"第一年春"类比）

- **Day 0（新手引导）**：进入校园，解锁"我的空间"（含种植台），发现第一个地点（旧礼堂），学会记录一条记忆节点。
- **Day 1–3（表层熟悉）**：采集、钓鱼/养鱼、拜访一两位 NPC、拍下第一批图鉴照片，图鉴出现第一批条目，探索度稳步上升，今日世界播报开始引导每一天。
- **Day 4–7（可选彩蛋）**：探索度 / 图鉴达阈值时，或依一条传闻在特定时间地点蹲守，可能首次偶遇一次异常 / 过去地图碎片——这是一次"可遇不可求"的惊喜，而非必须达成的阶段目标。多数玩家此阶段的重心仍是把生活过好。
- 此后进入自由循环，玩家自选路线。

## 9. 范围与优先级

### P0（核心，一定做）

地理地图 + 六边形迷雾、探索/足迹、地点系统、时间/天气/世界状态（含真实天气源接口）、日记 + 记忆节点、世界图鉴、采集、种植、钓鱼/养鱼、加工（简化产线）、建设与自由建造、资源与货币（六类 + 三币）、数据驱动内容层。

### P1（第二层，非常值得做）

工具升级线、宠物/友善生灵、稀有变异收集、随机事件、NPC 与熟悉度（含 API 轨）、传闻、世界异常（特殊任务）、历史第二张地图、轻社交（可配置，前移）、节日、真实信号接入、实拍识别与相机、地点微仪式/轻交互、今日世界播报（上提）、可变世界与周期洗牌（强化可感知）、开发者可视化编辑器。

### P2（有余力再做）

## 11. 附录：技术方向（待下一步专门讨论）

承接技术栈与架构议题，标记为下一步议题（docs 的 `03_TECH_STACK.md` 等将据此更新）：

- **前端**：Kotlin + Jetpack Compose + Android Location + 地图 SDK（开源瓦片方向）+ Camera/Photo。
- **相机/实拍与 AR**：
  - 相机：CameraX + Photo Picker（记忆节点、实拍识别）。
  - AR 双轨：ARCore（设备端锚定/平面跟踪，主验证）+ CameraX/IMU 伪 AR 叠加（无 GMS 兜底验证）。两条路线都做"AR 观察窗"验证。
  - AR 在架构上只是表现层可选视图，输入 `DerivedState`，领域层不依赖 AR/相机。
- **业务层**：World / Exploration / Event / Diary / Memory / NPC / Signal(真实信号) / AR(视图) 等模块。
- **本地**：Room；世界数据以 JSON / 数据表形式存储，由内容引擎读取；`ar` 字段作为可选内容字段。
- **网络**：REST API，轻社交低频写入；真实天气/校园信号走可配置外部源；多人实时需求用 WebSocket，后补。
- **后端（后续补齐）**：账号与云存档、足迹、漂流瓶、共享记忆、声望榜、未来 UGC 分享。
- **工具链**：开发者可视化编辑器（内容录入工具）。
- **未来扩展**：网页版、Unity / AR。

是否采用该方向、地图 SDK 选型、后端必要性、真实信号源选型，留待技术阶段结合"真实坐标 + 虚拟叠加层 + 真实信号 + AR"与课设工作量重估。
